# 显存与消费级设备指南

Q-LAMT 的目标是：在消费级显卡上做**定点行修复**，让完整模型以 4-bit 常驻，FP16/BF16 基座留在磁盘，只给少量行分配梯度。

下面是实测数字，以及这些数字**不**代表什么。先给结论：

> 7B NF4 在 RTX 4070 Ti 12G 上加载 5.18G，训练峰值 6.44G。比全量微调低一个数量级，但与 QLoRA 同档，不是新的显存范式。完整 NF4 模型仍常驻；只有**可训练集**很小。

英文版：[VRAM.en.md](VRAM.en.md)。

## 实测数字

环境：Qwen2.5-0.5B/7B-Instruct，bitsandbytes NF4，compute dtype bf16，RTX 4070 Ti 12G，桌面约 4G；batch 1–2，短 prompt，最大序列 256，Windows 10。

| | 0.5B | 7B |
|---|---:|---:|
| NF4 权重 allocated | 0.43G | 5.18G |
| NF4 权重 reserved | 0.62G | 5.52G |
| 训练峰值 allocated | 0.98–1.50G | 6.44G |
| 训练峰值 reserved | 1.01–1.50G | 6.50G |
| 加桌面约 4G 的总占用 | ~5–5.5G | ~10.4G |
| 单次修复墙钟 | 25–50s | 68–75s |
| 全量微调对比 | 4G+ 权重/优化器 | >100G |
| QLoRA 对比 | — | 约 5–7G（同档） |

7B 峰值包含整个进程：NF4 加载 + 激活 + 行参数/优化器 + 临时反量化 buffer。运行后基座 4 个分片与源模型 `samefile`，未被改写。

## 什么常驻、什么不常驻

**常驻：**

- **整个模型的 NF4 权重**。稠密 Transformer 层是串行的，前向和反向激活图都需要所有层。
- **反向激活图**：通常是 4-bit 权重之后的第二大项。
- **点名行参数**（`P` 或 `ΔR`，float32）+ AdamW 状态。7B 64 行约 2.46MB 参数、9.83MB 优化器估计。
- **临时反量化 buffer**：splice 具象时一次一层矩阵。

**不常驻：**

- 完整 FP16/BF16 基座。它是在磁盘上的 safetensors 账本，只按行读取。
- 全模型权重梯度。基座冻结。
- 基座优化器状态。
- 每个点名层的常驻 BF16 副本。修正项直接加在 QLinear 输出上，没有 `W_eff=buffer.clone()`。
- Adapter。release 可以是合并后的单模型。

## “只加载激活路径”为什么不成立

在稠密 Transformer 里，第 L 层的激活行计算 `y_i = W[L,i]·x_L`，而 `x_L` 是第 L-1 层**所有行**产生的完整激活向量。激活行是输出的子集，不是自包含的输入路径：

- 跳过未激活行会改变 `x_L` 和下游所有计算；
- 激活集是输入相关的，必须先算完整前向才知道；
- 现代 SwiGLU LLM 没有 ReLU 硬零，“未激活”行仍有小贡献；
- 只有 MoE 才能按 token 只加载热专家；Qwen2.5 稠密模型不是 MoE。

所以行映射是**训练掩码 + 审计记录**，不是“前向可以省略哪些权重”。

## 显存公式

```text
峰值 ≈ NF4 权重
     + 激活图(batch, seq, hidden, layers)
     + 临时反量化(max layer matrix)
     + 行参数 + AdamW(selected rows)
```

行参数项很小；把点名行从 1000 降到 64 只省几 MB，不是几 GB。大杠杆是 4-bit 基座、激活内存、以及不加载完整 FP16 模型/优化器。

## 为什么基座是 4-bit 而不是 FP16

- 7B FP16 权重约 15G，再加激活，12G 卡放不下；
- NF4 把完整模型压到 5.18G，12G 消费卡可以跑修复；
- FP16 账本仍是点名行和合并的真值，只按行从磁盘读取，不作为模型加载；
- 训练目标就是部署的 NF4 函数；全 FP16 前向在 0.5B 可行，7B 在这类卡上不可行。

## 与 QLoRA 的对比

7B QLoRA 通常约 5–7G（冻结 4-bit 基座 + 小 adapter）。Q-LAMT 在同一档（实测 6.44G）。优势不是“显存低很多”：

- Q-LAMT 按失败选择/消融行；QLoRA 在数据集上训练稠密低秩 adapter；
- Q-LAMT 可以保留 FP16 基座并版本化稀疏 sidecar；QLoRA 需要 adapter 管理和合并/重量化决策；
- Q-LAMT 数据极省且行级可审计；QLoRA 通常更适合大规模领域适配；
- 两者合并成单模型都有量化损失；Q-LAMT 把最终量化检查显式化。

## 真正降低峰值的杠杆

1. **基座保持 NF4**（7B 最大单项收益）。
2. **不加载 FP16 基座**；按行读磁盘。
3. **小 batch / 短序列**（实验用 batch 1、max 256）。
4. **冻结基座，不分配基座优化器状态**。
5. **correction-only 前向**，不为每个点名层保留 BF16 副本。
6. 激活是瓶颈时用**梯度检查点**（默认未开；hooks 与 checkpointing 需要集成测试）。
7. **会话级卸载**：一次修复/一批之后卸载，不是阶段间卸载。

不能降低峰值的：

- 只加载激活行（前向仍需要其余行）；
- 在定位/消融/训练之间卸载（会重跑前向）；
- 单独缩小行参数（本来只有 MB 级）。

## 消费级显卡建议

| 显卡 | 0.5B NF4 | 7B NF4 |
|---|---|---|
| 8G | 舒适 | 未验证；可能很紧，建议 batch 1、短序列、关闭其他 GPU 应用 |
| 12G | 舒适 | **实测**（桌面约 4G） |
| 16G | 舒适 | 舒适 |
| 24G | 舒适 | 舒适，可增大 batch/序列 |

7B 数字是在 12G 卡、桌面占约 4G 时测的。无头 8G 卡在 batch 1/短序列下**可能**能跑，但未验证，不能当作支持。13B NF4 未测。


## 重要边界

- 这些数字来自**构造性修复任务**，不是完整 benchmark 训练。
- 成功运行的行位移超过规格 15%/30% 守卫；显存可行不等于守卫成立。
- 完整 NF4 模型常驻；不是“没有全模型”。
- release 会临时持有基座副本并写发布模型；规划磁盘，不只规划显存。
- NF4 不是 MXFP4；不同 4-bit 格式的 kernel/scale/显存行为不同。
