# Q-LAMT 与其他方案对比

Q-LAMT 不是更强的通用训练方法。它占的是一个特定生态位：

> **失败样本很少、需要行级审计/回滚、部署在量化模型上，而且修改必须经得起重量化。**

它的对手是模型编辑与稀疏适配，不是预训练或大规模领域微调。英文版：[COMPARISON.en.md](COMPARISON.en.md)。

## 对比表

| 方案 | 数据需求 | 泛化 | 7B 显存 | 审计/回滚 | 部署一致性 | 主要弱点 |
|---|---|---|---|---|---|---|
| 全量微调 | 大领域数据 | 最强 | >100G | 无行级；checkpoint 级 | 同权重，再量化 | 遗忘、成本 |
| LoRA / QLoRA | 领域数据 | 好 | ~5–7G | adapter 级，非行级 | 合并/重量化有坑 | 数据、adapter 堆积、不可解释 |
| ROME / MEMIT | 一条事实 | 限于该编辑 | 低 | 单次编辑，无训练回环 | 常在 FP16，部署不同 | 闭式假设、耦合、副作用 |
| FISH / 稀疏微调 | 领域数据 | 好 | 低优化器 | 掩码级 | 合并/重量化 | 掩码来自数据，不是单失败因果 |
| 激活干预 / ITI | 激活样本 | 行为级 | 低 | 可逆干预 | 不改权重 | 推理开销、不持久 |
| RAG / prompt | 无训练 | 知识级 | 推理成本 | 外部 | 不改模型 | 不改权重/格式 |
| **Q-LAMT** | **1 失败 + 释义** | **局部** | **6.4G 峰值（实测）** | **行级 + 版本链** | **NF4 上训练，release 复验** | 单次成本、范数预算、复杂度 |

## Q-LAMT 真正改善的

### 1. 相对 LoRA/QLoRA 的数据经济性

LoRA/QLoRA 需要数据集；Q-LAMT 只需一个失败 + 几条释义。数据收集是瓶颈、失败稀少且重要时，这有价值。

它**不**在大而全的领域数据集上赢 LoRA。那种场景 LoRA 更简单、通常更强。

### 2. 相对 adapter/FP16 编辑的部署一致性

Q-LAMT 在部署的 NF4 上定位、消融、训练、验收；最终把 FP16 行合并、量化一次、复验。QLoRA 训练 FP16 adapter 再合并到 4-bit 是已知有损步骤；ROME/MEMIT 常在 FP16 上编辑，部署后可能漂移。

这是真实差异，但不免费：splice 在混合前向里训练 FP16 行，最后仍要过量化；release 复验必须做。

### 3. 行级审计与回滚

每个编辑都有：

- `(layer,row)` 地址；
- float32 sidecar 快照；
- manifest（base sha、sidecar sha、配置哈希、失败哈希、指标、parent）；
- `current` 指针与 release manifest。

LoRA 可以按 adapter 版本化，但不是行级。ROME/MEMIT 通常没有训练/回归/版本链。全量微调只有 checkpoint，不解释改了哪些行。

### 4. 结构性的遗忘控制

99.9% 参数冻结；background KL、上一版 KL、回归集是显式检查。全量微调没有这种结构保护；LoRA 侵入性小但仍是分布式更新；本方案把邻域检查放进管线。

7B 实验背景 KL 0.0026–0.0043，但背景集只有 16 条短句，不等于完整 benchmark。

### 5. 无 adapter 堆积

release 可以是合并后的单模型。多任务 LoRA 服务常需要堆 adapter 或路由。Q-LAMT 的 sidecar 有版本并可回滚，但发布仍要合并/复验。

### 6. 因果过滤

激活幅值是召回，消融判断“置零后行为动不动”。FISH 用数据上的敏感度掩码；Q-LAMT 按失败选行并可审计。

注意：实测 fallback 行经常占相当比例（0.5B 某格式 27/32，7B Valdoria 16/64）。简单任务往往高激活就够；消融是精度/高风险工具，不总是决定因素。

### 7. 领域复用

同域失败在行上高度重叠。一个领域可以成为一个版本化 sidecar 热行集，带上一版 KL 和累计回归。这是 Agent/code/格式/identity 修复最有价值的场景。

## Q-LAMT 输的地方

### 单次成本

仅消融就可能几百次前向（7B Valdoria：368 个 forward pair，29.8s）；单次修复 68–75s。ROME 是秒级；LoRA 在大量样本上摊薄成本。Q-LAMT 不是最便宜的单次编辑。

### 编辑幅度

规格 15%/30% 守卫**没有**被成功运行满足：

- 0.5B：2.3–4.6 倍行范数；
- 7B：1.61–2.28 倍累计。

参数个数很小，但位移很大。称它“外科手术式小改动”在幅度上不准确。它是**计数稀疏**，不一定是**距离小**。

### 目标难度

7B Valdoria/identity 过；7B Orion 0.667 被拒。固定行数/步数不保证每个事实。机制成立，目标和预算决定成败。

### 相对 QLoRA 的显存

7B NF4 峰值 6.44G，QLoRA 同档（约 5–7G）。优势不是“显存低很多”，是治理/数据/部署一致性。完整 NF4 模型常驻，不是“只加载路径”。

### 复杂度与运维

sidecar、manifest、current、release、回归集、分片写入、base sha 比一个 LoRA 文件复杂。需要审计/回滚/多轮安全时值得；不需要时是负担。

### 泛化与评测

证据是：0.5B 12 条构造样本、7B 两个成功目标（Valdoria、identity）、16 条短背景；没有 MMLU/IFEval 级评测；没有 20–50 条顺序实验。这是机制验证，不是能力声明。

## 每一步都必需吗？

不是。有最小核心和一组稳健性层。

### 核心闭环

1. **量化现场**：部署如果是 NF4，就必须在 NF4 上测；否则测的是另一个函数。部署 FP16 才用全 FP16，但 7B 显存不现实。
2. **定位（某种选择器）**：用于选行；激活 top-k 最便宜，梯度/Fisher/随机也可。没有选择器，全行消融不可行。
3. **训练行**：核心修复环。单条孤立事实可用 ROME 闭式解替代；多事实/行为类失败需要迭代训练。
4. **验收**：**不能省**。无 EOS 时 teacher-forced 12/12、自由生成 5/12；7B Orion 被验收拒绝；没有发布前量化复验，线上模型可能没有修复。
5. **部署**：合并+量化成单文件，或保留 base+sidecar 混合；必须显式。

### 稳健性层

| 步骤 | 对什么是必需的 | 可以去掉当 | 证据/说明 |
|---|---|---|---|
| 消融确认 | 精度、高风险事实 | 简单/高激活场景、可信领域热行 | fallback 行常完成简单任务 |
| 阈值校准 | 更好的假阳性控制 | 可接受固定阈值 | 成本小 |
| background KL | 遗忘控制 | 用 held-out benchmark 替代 | 至少要一种邻域检查 |
| 上一版 KL | 多轮连续性 | 只做单次 | 防止覆盖旧修复 |
| 回归集 | 多轮安全 | 只做单次 | 抓“修 A 坏 B” |
| EOS 目标 | 精确自由生成 | 只接受 teacher-forced | 5/12 vs 12/12 |
| sidecar/版本链 | 多轮、回滚、审计 | 一次性合并足够 | 避免反复改基座 |
| 累计守卫 | 多轮风险 | 一次性编辑 | 风险政策，不是物理定律 |
| 15%/30% 守卫 | “小改动”承诺 | 接受大位移 | 我们的运行超过它 |
| 分片 release | 单文件 15G/低内存 | 基座已分片或很小 | 7B 分片基座没走这条 |
| 每版临时量化 | “accepted=可发布” | 接受最终 release 检查 | v0.1 偏差 |
| 层间均衡 top-k | 成本/精度 | 随机/全局 top-k | 非硬性要求 |

### 去掉某一环会怎样

- 去掉消融 → 更快，更多假阳性；简单任务可能仍成。
- 去掉验收 → 不可接受；不知道生成/量化后是否还有效。
- 去掉 sidecar/版本 → 单次可以；多轮累积、回滚弱。
- 去掉 background/回归 → 可能破坏无关行为或旧修复。
- 去掉 release 量化检查 → 线上 NF4 可能没有修复。
- 去掉 EOS → 只学目标前缀，不会停。
- 去掉范数守卫 → 仍能跑，但“外科手术”说法消失。

## 什么时候用哪个

- **一条孤立事实、不管审计、追求快**：ROME/MEMIT。
- **大范围领域适配/能力提升**：LoRA/QLoRA + 数据。
- **失败少、要审计/回滚、部署一致、数据稀缺**：Q-LAMT。
- **Agent/code/格式行为，同域失败**：Q-LAMT + 领域热行 sidecar。
- **只做激活干预、不改权重**：activation steering/ITI。
- **不加知识进模型**：RAG。
- **能力提升**：不要用稀疏行方法；用数据 + 全量/LoRA。

诚实的总结：Q-LAMT 的优点是**治理、数据经济性、部署一致性、行级可逆性**；不是原始能力、吞吐，也不是相对 QLoRA 的显存数量级优势。
